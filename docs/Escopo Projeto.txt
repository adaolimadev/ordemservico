Documento de Escopo: Sistema de Gestão de Ordens de Serviço (OS)

1. Visão Geral
Problema: Necessidade de gerenciar Ordens de Serviço de maneira centralizada, confiável e escalável, superando a falta de controle e rastreabilidade atual.
Objetivo: Desenvolver uma aplicação web para o gerenciamento completo do ciclo de vida das Ordens de Serviço (OS) e seus indicadores operacionais.


2. Perfis de Acesso (Atores)
O sistema contará com controle básico de acesso dividido nos seguintes perfis:
Administrador
Atendente
Técnico
Gestor


3. Requisitos Funcionais (RF)
Ações e funcionalidades que o sistema irá entregar aos usuários.

Módulo de Usuários
RF01: O sistema deve permitir o cadastro, edição e consulta de usuários.
RF02: O sistema deve permitir a ativação e desativação de usuários.

Módulo de Clientes
RF03: O sistema deve permitir o cadastro, edição e consulta de clientes.
RF04: O sistema deve permitir a ativação e desativação de clientes.

Módulo de Equipamentos
RF05: O sistema deve permitir o cadastro, consulta e gestão de equipamentos vinculados aos clientes.

Módulo de Ordens de Serviço (OS)
RF06: O sistema deve permitir a criação e emissão de novas Ordens de Serviço.
RF07: O sistema deve permitir a alteração de status e o acompanhamento do andamento das OS.
RF08: O sistema deve permitir o registro de informações, diagnósticos e apontamentos de atendimento na OS.
RF09: O sistema deve permitir a conclusão ou o cancelamento de uma OS.
RF10: O sistema deve manter e permitir a consulta do histórico de alterações de cada OS.

Módulo de Relatórios/Dashboard
RF11: O sistema deve exibir indicadores operacionais e gerenciais.


4. Requisitos Não Funcionais (RNF)
Restrições técnicas e de qualidade arquitetural.
RNF01 (Plataforma): O sistema deve ser desenvolvido como uma aplicação Web.
RNF02 (Escalabilidade): A arquitetura deve ser escalável para suportar o crescimento do volume de OS.
RNF03 (Confiabilidade): O sistema deve ser centralizado e garantir a integridade dos dados (ACID) no banco de dados.


5. Regras de Negócio (RN)
As leis do seu sistema. O código do backend deve proteger essas regras a todo custo.

Regras de Equipamentos
RN01: Um cliente pode possuir múltiplos equipamentos (1:N).
RN02: Todo equipamento deve estar obrigatoriamente associado a um único cliente.
RN03: O número de série de um equipamento deve ser único no sistema.

Regras de Validação de Abertura de OS
RN04: Ao criar uma OS, o sistema deve validar obrigatoriamente se:

O cliente existe e está ativo.
Os equipamentos existem, estão ativos e pertencem ao cliente selecionado.
Nenhum equipamento inativo pode ser inserido em uma nova OS.

RN05: Todos os equipamentos listados em uma mesma OS devem pertencer ao mesmo cliente titular da OS.
Máquina de Estados da OS (Transições de Status)
RN06: Uma OS "Concluída" não pode retornar para o status "Aberta".
RN07: Uma OS "Concluída" não pode ser "Cancelada".
RN08: Uma OS "Cancelada" não pode transitar para o status "Em Execução".
RN09: O fluxo entre "Em Execução" e "Aguardando Cliente" é bidirecional (podem alternar entre si).
RN10: Validação onde não permita abrir uma OS com um equipamento que ja tenha uma OS aberta, a nao ser que ela esteja cancelada ou concluída.

6. Domínios de Dados
Valores fixos que irão popular seletores e tabelas.

Prioridades: BAIXA, MEDIA, ALTA, CRITICA.
Status da OS: ABERTA, EM_ANALISE, EM_EXECUCAO, AGUARDANDO_CLIENTE, CONCLUIDA, CANCELADA.
